# Регистрация и первичное рабочее пространство

## Инварианты

- До подтверждения email пользователь не получает JWT и не имеет доступа к workspace API.
- Verification token действует 24 часа, хранится только как SHA-256 hash и становится недействительным после повторной отправки письма.
- Подтверждение email, принятие приглашений и создание личного workspace выполняются в одной MongoDB-транзакции.
- У пользователя не больше одной личной организации (`Organization.personalOwner` имеет unique index).
- Личное рабочее пространство содержит активную подписку `free`, активный бессрочный период и стартовый проект «Проект».
- В организации пользователь имеет роль `owner`, в стартовом проекте — `admin`.
- Переименование стартового проекта не влияет на повторяемость provisioning: его идентификатор хранится в `User.starterProject`.

## Сценарий

1. `POST /api/auth/register` валидирует данные, сохраняет не подтверждённого пользователя и email intent.
2. Email worker отправляет ссылку `/verify-email?token=...`.
3. `POST /api/auth/email/verify` начинает транзакцию и повторно проверяет hash, срок токена и статус пользователя.
4. В транзакции пользователь получает `emailVerifiedAt`, принимаются актуальные приглашения и выполняется `provisionPersonalWorkspace`.
5. Создаются или восстанавливаются связи с личной организацией, подпиской Free и проектом «Проект».
6. API возвращает JWT и `onboarding.projectId`; frontend предлагает сразу создать первую задачу.
7. Проект можно переименовать через `PATCH /api/projects/:projectId`, второй проект — создать через `POST /api/projects`.
8. Третий активный проект блокируется лимитом Free и ведёт пользователя в раздел «Тарифы».

## Отказоустойчивость

Если любой шаг транзакции завершается ошибкой, активация пользователя и все workspace-ресурсы откатываются. Исходная verification link остаётся пригодна для повторной попытки до истечения срока или ротации токена.

Повторное успешное использование ссылки запрещено. Для устаревшей или повреждённой ссылки frontend предлагает `POST /api/auth/email/resend`; endpoint не раскрывает, существует ли указанный email.

## Ответ подтверждения

```json
{
  "token": "session-jwt",
  "user": {},
  "onboarding": {
    "organizationId": "...",
    "projectId": "...",
    "projectName": "Проект",
    "plan": "free",
    "isNewWorkspace": true
  }
}
```
