# Шаблоны проектов

## Пользовательский сценарий

В разделе «Шаблоны» есть две вкладки: задачи и проекты. Для проектов доступны
три встроенные заготовки: неделя руководителя, запуск клиентского проекта,
рабочая смена магазина. Перед созданием пользователь видит категории, задачи,
чек-листы и относительные сроки, задаёт название проекта и дату начала.

Администратор любого доступного ему проекта может сохранить его структуру в
личную библиотеку. Другие пользователи не видят этот шаблон. Удаление шаблона
не удаляет проекты, созданные из него; удаление исходного проекта также не
удаляет сохранённую заготовку.

Копируются категории, задачи со статусами open/in_progress, их описания,
приоритеты и тексты чек-листов. Задачи на проверке, выполненные и закрытые
исключены. Участники, ответственные, наблюдатели, аватар, файлы, комментарии,
история и расписания повторов не переносятся. В новом проекте администратор
и инициатор задач — текущий пользователь; все задачи открыты и не назначены,
все пункты чек-листа не отмечены. Категории и пункты получают новые ID.

Сроки сохраняются как календарное смещение от дня сохранения шаблона
по Europe/Moscow. Просроченные сроки становятся нулевым смещением.
При создании смещения отсчитываются от выбранной даты начала; время срока —
18:00 по Москве. Задачи без срока остаются без срока.

## Лимиты и безопасность

В шаблоне максимум 30 категорий, 50 задач, 40 пунктов в каждом чек-листе.
Превышение возвращает понятную ошибку, а не молча обрезанный проект.
Максимальная длина названия — 160 символов, описания задачи — 10000,
пункта чек-листа — 1000.

Пользовательские шаблоны учитываются вместе с существующими шаблонами задач
в лимите templates личной организации: бесплатный — 3, Команда — 50,
Бизнес — 200. Встроенные заготовки лимит хранения не расходуют.
Создание проекта расходует лимиты проектов и активных задач именно личной
организации пользователя, даже если исходный проект принадлежал другой компании.
Проверяется весь набор сразу. При нехватке лимита ответ 402 содержит
limit_exceeded и информацию для перехода на тариф; владельцу/администраторам
организации создаётся уведомление с существующим ограничением частоты.

Проект, категории и задачи записываются одной транзакцией. Ошибка не оставляет
частично созданный проект. Операции создания из шаблонов сериализованы по
личной организации; это не заменяет отдельный аудит конкурентных лимитов
старых путей создания обычных проектов и задач.

Требуется MongoDB replica set или sharded cluster с поддержкой транзакций.
Standalone MongoDB не поддерживается этим сценарием. Новая коллекция
projecttemplates создаётся Mongoose. На Project добавлен уникальный sparse
индекс templateCreationKey; при отключённом autoIndex создайте его до выпуска:

```js
db.projects.createIndex({ templateCreationKey: 1 }, { unique: true, sparse: true })
db.projecttemplates.createIndex({ owner: 1, createdAt: -1 })
db.projecttemplates.createIndex({ organization: 1 })
```

Миграция старых проектов не требуется. Поля идентификатора запроса, его хеша
и журнала не возвращаются в JSON проекта.

## API

Все endpoints требуют подтверждённого обычного пользователя.

- GET /api/project-templates — встроенные и личные заготовки, ответ templates.
- POST /api/project-templates — { projectId, name }, сохранить структуру проекта,
  только администратор исходного проекта; ответ 201 с template.
- DELETE /api/project-templates/:templateId — удалить свой шаблон.
- POST /api/project-templates/:templateId/projects — { name, startDate, requestId },
  создать проект; startDate в формате YYYY-MM-DD, requestId — UUID.
  Ответ 201 с project, при повторе того же запроса — 200 с тем же проектом.

Повторный requestId с изменёнными параметрами возвращает 409. После сетевой
ошибки интерфейс повторяет запрос с прежним UUID, если параметры не менялись.
Ключ сохраняется в созданном проекте; после окончательного удаления проекта
защита от повтора старого запроса не сохраняется бессрочно.

## Проверка

Из backend, с адресом отдельного тестового replica set:

```sh
TEST_MONGODB_URI='mongodb://127.0.0.1:27017/test?replicaSet=rs0' npm test
```

Новые тесты: project-templates.test.js и project-templates.integration.test.js.
Проверяются копирование только разрешённых данных, сроки, новые ID, сброс
чек-листов, права, тарифы, откат при ошибке, одновременные одинаковые запросы
и повтор после сетевого сбоя. Production DB и SMTP для тестов не используются.
